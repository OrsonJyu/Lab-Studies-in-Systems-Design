## 私有信息从哪里取

共享仓库只保存字段模板。当前真实共用 JSON 位于本机仓库根目录忽略的 `.local/wired-lab.json`；进入 `.local/` 后先确认权限和设备身份，不在聊天/PR 输出其完整内容。它包含 SSH 目标、原可信密钥别名、接口、地址和现有 profile UUID，不含密码或流 URI。

流 URI 留在板卡已有私有配置中，可能在 URI 路径内带访问参数。不得只遮 netloc/query 就认定已去凭据。离线备份目录包含网络凭据和文件系统元数据，不上传。临时 SSH socket 会过期，接手时重新认证，不把 socket 存在当作可达证明。

## 下一阶段，按用户 2026-11-03 的讨论

1. 用手代替 gecko，运动触发保留片段；连续静止超过 n 秒结束，静止未满 n 秒又运动则续接同一事件。
2. 区分现场到显示延迟、到达帧后的检测延迟和保存片段是否缺开头。连续原流作片段对照，独立计时画面/参考相机检查端到端延迟。
3. ROCK 持续接收并保留滚动缓存，触发时纳入前段；不能把 RTSP 接收缓冲直接视为相机历史回看功能。这台相机是否支持历史读取仍未知。
4. 有时间再加网站：实时画面、录制状态和已保存片段。拖动回看是另一个需要明确保留机制的功能。

`n` 为静止结束阈值、`p` 为触发前保留长度。`n=5 秒`、`p=3–5 秒` 只是讨论示例，尚未成为用户确认的最终参数。接续时先确定参数/验收，再实现；不能凭手的测试宣称识别 gecko 或行为。用户此前明确先讨论，当前本次工作只整理和统一网络，没有自动开始录制实验。
