# 版本与历史规则 / Versioning

## 三种不同的历史

1. **Git commit** 记录每次文件变更；提交说明写清实际结果。
2. **仓库版本** 由根目录 `VERSION`、`CHANGELOG.md` 与同名 Git tag `vX.Y.Z` 共同标识。
3. **项目决定与实验历史** 记录在 DECISIONS、HISTORY 与实验记录，保留原工作日期。导入材料的日期不能冒充当日新实验。

## 版本含义

- `0.x.y`：档案建立与整理阶段，仍有迁移/结构事项未完成。
- `1.0.0`：首个整理完成的可访问资料基线；表示档案里程碑，**不表示摄像头系统已完成**，也不表示不可获得的材料已补齐。
- `PATCH`：修复说明、链接、索引或补充不改变主要结论的证据。
- `MINOR`：新增阶段成果、实验、文档分区或经过确认的新决定。
- `MAJOR`：改变公开接口、目录约定或项目基线，导致旧使用方式不再成立。

新增源码的运行版本应在自身说明中独立记录；仓库版本不替代 Arduino core / IO_Control / FFmpeg 等环境版本。

## 每次阶段更新

更新状态、来源、决定和知识网 → 检查链接与文件校验 → 提交 → 上传源码及 LFS 对象 → 核对远端 → 建立版本标签。走 PR 的改动在合并进 `main` 后再打标签；分支规则见 [CONTRIBUTING](../CONTRIBUTING.md)。不要移动旧标签，不要 force-push 覆盖共享历史。

只有在用户明确要求时才建立定时同步/提醒。当前是按工作阶段维护，不声称后台持续监控。
