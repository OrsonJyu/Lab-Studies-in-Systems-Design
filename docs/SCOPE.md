# 项目范围 / Scope

依据：[展示 PDF](../project-camera/references/SD5531_Gecko_Presentation_Group2.pdf) p.3–9、[合作计划](../project-camera/references/Gecko_各组合作计划.pdf)、[主讨论](history/main-videoing.md)。本页是带来源的整理，不新增团队承诺。

## 使用目标

让学生、教师与照护者能够找到守宫行为证据、比较日期/环境变化，并形成可核对的观察问题。学生选择片段并请教师审阅属于展示中的扩展方向。

## 完整工作范围

| 层次 | 计划能力 | 验证边界 |
| --- | --- | --- |
| 采集与保存 | 视频和热阵列数据、录制、保存、取回与访问 | 需实际设备连接、稳定性与回放证据 |
| 定位与身份 | 图像中的位置、个体花纹匹配探索 | 定位与个体识别分开；不可见/不足时输出 Unknown |
| 行为信息 | 活动/静止、区域进出与停留、候选饮水/进食/排泄事件 | 候选事件必须能回放核对；不可见不能算未发生 |
| 空间与时间 | 轨迹、停留热力图、活动时间分布 | 需要持续或定期观察，不能仅由触发片段推断全天 |
| 热阵列 | 有效可见时期的表面温度阵列及环境关联 | 测量条件与性能需实验；不可测时保留缺口 |
| 共享与集成 | 按时间、区域、个体和设备关联其他组记录 | 接口、事件标签和整合负责人共同确认 |
| 安装协作 | 机位、视野、遮挡、固定、布线、拆洗 | 与总体设施和功能模块共同试拍 |

## 当前第一步

先让一条视频流经过接收、循环缓存和事件触发后，产出包含触发前画面的可播放片段，并留下对应事件记录。测试触发可由人工发出，以便分别验证录制链路与运动检测。

`n` 秒预录、缓存期限、事件后保存长度、“一天”是否为保留策略、重叠事件如何合并，都尚未成为已确认参数。示例 5 秒不能自动成为需求。

## 范围外与未承诺事项

展示 PDF p.8 将自动异常检测和健康诊断排除在当前交付之外。旧 Figma Frame 10/16 仍出现相关探索文字，应作为旧扩展设想保存。独立完整 App、最终算法、全部摄像头数量、全班数据库标准和云端部署均不能从示意图推定为已落实。

为其他组提供录像，不自动等于本组负责全部排泄物/摄食识别算法。Project 编号也不等于 Team 编号。
