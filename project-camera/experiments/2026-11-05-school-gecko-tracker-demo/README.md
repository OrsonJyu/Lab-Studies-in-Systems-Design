# 2026-11-05 · school 守宫定位与锁定的第一次实机演示

日期：2026-11-05（香港）16:22–16:27。代码为分支 `code/gecko-tracker`（提交 `1a31546`）。用绿色玩具蜥蜴代替守宫，放在桌面上，由用户拉动。录像里没有拍到人脸；片段在用户 Mac 的 `recordings/`，未放入仓库。

| --- | --- | --- |
| 16:22:43–16:22:46 | 生成背景 → 未锁定 | 蜥蜴在画面里，进入了背景（符合设计） |

另外两个问题：

1. **框只框住了尾巴末端**：框的范围约 x 23–29%、y 81–87%，而蜥蜴约占 x 20–45%、y 67–87%。原因是只用灰度：在 16:27 截图上，蜥蜴身体灰度 157、桌面 156–186，差值大多低于前景阈值 30；只有颜色较深的尾巴末端（142）够得上。颜色上差别很大：蜥蜴 U≈58–64、V≈68–89，桌面 U≈102–115、V≈137–145。
2. **检测区域与实际画面不符**：区域是我根据 16:21 的截图画的，那张图里一块板子挡满了镜头；演示时镜头对着桌面，区域覆盖了左下方桌面和部分板子。蜥蜴仍在区域内，不影响本次结论。

手伸进去、开关灯、再次拉动（第 4–6 步）在日志里没有出现：16:25:22 之后到 16:27 没有运动、环境变化或跟踪状态变化，这三步没有评估。

## 解读

- 锁定、跟随移动、静止时保持并确认的流程能在实机上跑通。
- 只用灰度不够：前景要加上颜色差（U、V），才能把整只绿色蜥蜴分出来；真实守宫（黄色带斑点）与底材的颜色差也有帮助。
- 外观确认太严：长时间静止时摄像头自动曝光会让亮度慢慢漂移，应先减去各自平均亮度再比较，或连续几次不符才判丢失。

## 限制

- 只有一轮，第 4–6 步未评估。
- 颜色数值来自 800×448 截图的区域平均，不是检测程序内部 160×90 的值。
