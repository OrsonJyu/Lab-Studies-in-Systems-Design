# 2026-11-05 · school 调高运动检测灵敏度

日期：2026-11-05（香港）16:10–16:19。用户自己观察到移动玩具蜥蜴常常录不进去，要求先不执行"变化区域大小要合适"这条规则，并调高灵敏度。

## 改了什么

- 关闭大小规则（`motion.size_filter: false`）：检测区域内有变化就算，不论大小。
- 像素变化阈值 `pixel_threshold` 从 25 降到 15。
- 保留：整幅画面 ≥30% 同时变化不算；运动要持续 0.5 秒。
- 只改了 ROCK 上的 `config.json`（修改前已备份）；仓库默认值不变。

## 结果

| | 修改前（16:10:54–16:12:45） | 修改后（16:13:31–16:18:42） |
| --- | --- | --- |
| 被判"变化太小"的帧 | 每 10 秒 3–27 帧 | 规则已关闭 |
| "有变化但不够持续"的帧 | 每 10 秒 3–16 帧 | 共 130 帧 |
| 判为运动的帧 | — | 共 225 帧（静止 2,651 帧） |
| 用户观察 | 移动蜥蜴常录不进去 | **移动蜥蜴能录进去** |

修改后保存了 6 段，全部完整（12–32 秒）。画面静止的 16:13:51–16:14:11 共 201 帧全部判为静止，没有噪点误触发。

## 限制

- 用户把检测区域画成了几乎整幅画面（最后一次 9,101 / 14,400 像素），背景里的桌椅和人也在区域内，所以 6 段里有多少是蜥蜴触发、多少是背景触发，没有逐段核对。
- 同样因为区域太大，跟踪锁定到了背景物体，最后状态为"丢失"；守宫跟踪没有在这次评估。
- 灵敏度提高后，区域内的小虫、反光、轻微晃动也更容易触发；在真实饲养箱里需要重新评估。
