# 你们的 Project 2，到底在做什么？

## 核心理解

你们在做豹纹守宫饲养系统的“观察与记录模块”：把现场发生的行为留下来，让学校师生和照护者能够回看、比较，并逐步分析。做摄像头连接只是基础，设计问题是：**使用者想了解什么，你们提供什么可用的观察证据？**

例如，另一个组改变了隧道的结构。以前只能凭偶尔看到的情况说“它好像更喜欢这里”。有你们的模块后，可以查对应时段的录像，并比较进入隧道的次数、停留时间或活动事件。这样的结果支持进一步观察，但还不能单凭活动多就断言守宫更健康、更开心。

依据：A 10:00–12:49、15:33–19:29、28:01–32:28；B 08:27–09:04。这里的指标选择尚待团队和老师确认。

## 系统里有两条不同的数据路线

```text
普通摄像头 → 影像／视频流 → PC 或嵌入式板 → 视频文件存储
                                              ↓
                                    回放、片段检索、活动事件

热阵列传感器 → 温度阵列数据 → 采集／通信模块 → 后端记录
其他组传感器 → 环境／设备数据 ─────────────→ 按时间关联
                                              ↓
                                  网页展示、学生观察、照护参考
```

这是 AI 概念图，不是已定架构或最终接线图。视频是大量连续图像；热阵列是空间中的一组温度读数。两者可以互补，但不应混为一种“摄像头”。数据可以集中管理，也不意味着所有视频二进制内容都必须直接塞进同一个数据库。

## 老师为什么一直把话题拉回 scope？

从会议问答看，大家容易从“要用什么技术”跳到“做自动分析、识别多只守宫、做 3D 展示或大模型”。但如果视频还取不出来、数据没有稳定留下，这些分析就没有输入。

因此可以把工作分成三层：

1. **基础交付层：** 可靠采集、存储、取回和查看；热阵列基础读取；安装、走线和必要的共享接口。
2. **小范围分析层：** 选择一个有用问题，试活动事件或隧道进出统计，并用人工观察检查结果。
3. **扩展探索层：** 个体花纹识别、多摄像头关联、更复杂的机器学习或三维展示。

这三层是 AI 建议的优先级，不是老师给出的新增评分表。B 01:02–01:35 表明简单录像已有价值；A 33:33–37:55 强调先获得数据再考虑模型。官方 Project 2 仍包括视频与热阵列等范围；若要缩减，需说明原因并与老师确认。

## AI 想法可以放在哪里？

会上有人提出，能否把持续截图／视频交给 AI，像分析人的日常一样分析守宫。指导性回应把重点放回数据采集，并讨论传统视觉方法或较简单模型。

这不等于“AI 想法被否定”。比较稳妥的安排是：先把它放进扩展选项，写清它试图回答什么问题、需要哪些数据、怎样检查误判。不要把付费大模型 API 当成系统必须依赖，也不要先承诺自动判断动物健康。

例如，先用简单运动检测找出可能有活动的片段，再由人核对，可能已经减少大量翻录像时间。至于选择何种算法、计算设备和误差标准，需要实测后决定。出处：A 30:50–31:17、32:34–37:55。

## 技术探索具体怎么做？

下面是 AI 建议的最小验证顺序。不是说你们已完成，也不是要求 Assignment 2 前全部完成。

| 先回答的问题 | 可保存的证据 | 为什么重要 |
| --- | --- | --- |
| 指定摄像头能否在 PC 上连接并取得视频？ | 型号、网络配置说明、连接日志、短录像 | 先消除“硬件买来但拿不到数据”的风险 |
| 保存的视频能否按时间找到并回放？ | 文件、时间索引、回放截图／短演示 | 用户需要可用记录，而不只是实时窗口 |
| 连续录制会占多少空间？ | 实测码率与文件大小，明确相机数量和保留时长假设 | 不把会议中的估计数字直接当硬件规格 |
| 触发录像会不会漏掉小动作？ | 与连续录像／人工观察对照的样本 | 省空间不能以不知情的数据缺失为代价 |
| 日夜／灯光变化会怎样影响检测？ | 正常活动、无人活动但光照变化的对比片段 | 区分真运动与画面变化 |
| 热阵列在目标距离能读到什么？ | 原始阵列、采样条件和异常记录 | 温度精度、分辨率和对象识别是不同问题 |
| 其他组是否能理解和使用你们的数据？ | 一条样例记录、字段说明、对接结果 | 最终需要系统协作，不只是本组电脑能跑 |

涉及活体的验证前，先取得老师及相关照护人员的指导。基础连接、文件读写、接口及光照干扰可以先在不影响动物的条件下验证。

## 系统测试的四层意思

**单元测试：** 某个摄像头或传感器能否正常工作。

**模块测试：** 你们的采集、传输、保存和查看能否连起来。

**集成测试：** 接入共同后端、安装到 enclosure 后，还能否和其他组的数据与设备配合。

**系统测试：** 使用者在真实使用场景下，能否完成预期观察／照护任务。

这些例子是对课程测试要求的解释。摄像头在桌上成功显示一次画面，只能支持很小范围的成功，不能替代整套系统验证。来源：Final Project v43；A 20:07–23:05。

## 你们现在最值得做的三件事

第一，组内用一句话确认范围：服务谁、记录什么、提供什么查看／分析能力，以及哪些高级功能暂不承诺。

第二，把未知点变成实验：不用先猜“这个方案肯定可行”，而是列出相机取流、存储、热阵列读取和安装接口怎样验证。给每项明确负责人。

第三，带着具体问题找其他组和老师：相机装哪里、对方需要什么数据、你们需要什么环境数据、哪些器材可借、哪些要审批。团队编号先核实，不把 Project 1 当成 Team 1。
