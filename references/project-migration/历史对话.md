## 3. 两种视频方案的区别

### 首选：PoE IP Camera + Rock 5C + SSD

按你给的范围，数据路径是：

**网络摄像头 → 网络传输 → Rock 5C 接收及图像处理 → SSD 保存**

它把处理和存储集中到 Rock 5C。前期需要确认摄像头提供什么视频流与控制接口、PoE 供电设备由谁提供，以及 SSD 的连接方式。

### 备选：UVC Camera + ESP32-P4 + SD 卡

数据路径是：

**USB 摄像头 → ESP32-P4 → 本地 SD 卡录制 → 远程取回 → 后端保存**

它把录制放在本地节点，之后再收集文件。Espressif 的官方示例确认有支持 ESP32-P4 的 UVC 摄像头接入示例，但这只证明存在接入基础，**完整的录制、文件管理和远程取回仍需要实现与验证**。[官方 UVC 示例](https://github.com/espressif/esp-idf/blob/master/examples/peripherals/usb/host/uvc/README.md)

我的初步建议是：**按 scope 优先验证方案一，先跑通一台摄像头的完整录制链路，再根据实际问题判断是否启用方案二。** 目前不必同时完整开发两套系统。

## 4. 我认为最值得尽早明确的事

1. **每个区域到底需要什么信息？**  
   例如躲避屋需要判断是否进入、停留多久，还是需要完整录像？不同目标会影响位置、视野和录制方式。

2. **谁触发录制，其他组怎样取数据？**  
   连续录制、定时录制、人工触发、其他传感器触发，对模块的要求不同。

3. **视频和热阵列数据怎样对应？**  
   建议从一开始统一设备编号、区域编号和时间戳，便于以后把同一时刻的视频、温度分布与其他传感器数据放在一起分析。

4. **热阵列试验具体要验证什么？**  
   MLX90640 是 **32 × 24 像素的远红外热阵列**，提供的是温度分布信息。[Melexis 官方说明](https://www.melexis.com/en/product/MLX90640/far-infrared-thermal-sensor-array)  
   是否能在计划安装距离下区分守宫与背景、识别所需状态，需要实测；scope 中的 “different stage” 也还需确认具体指什么阶段。
